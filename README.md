# Стройплан 1.0

Локальный план строительных объектов. Реализуемый объём и история — в `plan.md`, требования — в `tz.md`.

## Запуск для разработки и просмотра

При установленном Node.js выполните в папке проекта:

```sh
node tools/serve.js
```

Откройте http://127.0.0.1:4173. Для постоянного использования нужен статический HTTPS-сайт; публикация пока не выполнялась. Двойной щелчок по `index.html` не является поддерживаемым запуском. Сборка и установка библиотек для интерфейса не нужны.

Для временной проверки с телефона в той же Wi-Fi сети запустите `node tools/serve.js <IPv4 компьютера> 4174` и откройте `http://<IPv4 компьютера>:4174/`. Компьютер и сервер должны оставаться включёнными. Адрес компьютера может меняться. Это локальный предпросмотр по HTTP; установка и офлайн требуют HTTPS (либо localhost на том же устройстве). База на телефоне отдельная, планы переносятся через JSON. Сервер раздаёт только файлы интерфейса из явного списка.

## Гант и печать

Раздел «Гант» показывает выбранные объекты, этапы и работы. Можно выбрать статусы, включить архив, изменить период и масштаб. «Сроки выбранных объектов» возвращает автоматический диапазон с учётом дочерних записей за границами родителей. Нажатие строки открывает форму, полосы — краткие данные. Изменение сроков не сдвигает остальные даты.

«Печать / PDF» готовит отдельный документ по текущим фильтрам, периоду и раскрытым строкам. «Раскрыть всё перед печатью» добавляет скрытых потомков. Все выбранные строки входят в печать, даже если экран ещё показывает только первую порцию. Предпросмотр сохраняет план на момент открытия; после новых правок откройте его заново.

По ТЗ 1.2 по умолчанию включено «Только работы выбранного периода»: для двухнедельного плана задайте начало и конец, остальные работы скроются вместе с ненужными строками объектов/этапов. Галочку можно снять для полного списка. «Кратко — объекты и этапы» помогает сравнить несколько объектов; «Подробно» показывает работы. Кнопка «Без завершённых» применяет существующий фильтр статуса. Эти действия не изменяют данные плана.

В предпросмотре выберите А3 или А4 и шрифт 9/10/11/12/14 pt (по умолчанию А3, 10 pt). Детализация и отбор по периоду наследуются из Ганта и доступны отдельно для печати. Дополнительное скрытие завершённых действует в рамках исходных статусов. Число листов пересчитывается; при более двух есть действия «Краткий вид», «Скрыть завершённые», «Выбрать объекты / период». Лимита два листа нет, данные не обрезаются, выбранный шрифт не уменьшается.

Документ разбивается по времени (до 31 дня / 13 недель / 12 месяцев, при необходимости меньше для выбранных бумаги/шрифта) и по высоте с повтором объекта/этапа на продолжениях. Длинные названия переносятся, подписи узких интервалов вынесены в заголовок. В системном окне сверяйте выбранную бумагу, альбомную ориентацию и поля 10 мм. На телефоне возможности зависят от системы; при ограничениях передайте JSON на компьютер.

Проверки нового раздела: `node --test tests/gantt.test.js`, `node tests/gantt-browser.cjs`. Для получения контрольных PDF установите `GENERATE_PDFS=1`; браузерный тест использует Playwright и Chrome по переменным `PLAYWRIGHT_MODULE`, `BROWSER_PATH`. Проверка PDF: `tools/check-gantt-pdf.py` с `pdfplumber`, Pillow и переменной `PDFTOPPM`, указывающей на Poppler. Отчёт — `output/step4-checks.md`. Для ТЗ 1.2: `node tests/print-options-browser.cjs`, контрольные PDF при `GENERATE_PDFS=1`, проверка `tools/check-gantt-pdf.py --compact`, отчёт `output/compact-checks.md`. Приложению эти библиотеки не нужны.

Браузерные проверки: `node tests/browser.cjs`, `node tests/browser-deep.cjs`, `node tests/finance-browser.cjs` и `node tests/files-browser.cjs` при доступном пакете `playwright` и браузере Chromium. Если пакет находится вне проекта, задайте `PLAYWRIGHT_MODULE` абсолютным путём к нему; для установленного Chrome/Edge задайте `BROWSER_PATH` абсолютным путём к исполняемому файлу браузера. Сервер должен работать на порту 4173. Проверки используют отдельные временные браузерные контексты, а не пользовательские данные. Проверка полного перезапуска создаёт отдельный временный профиль в системной папке временных файлов. `npm test` запускает тесты основной логики, финансов, обмена файлами, Ганта и правил печати.

Для установки только инструментов разработки: `npm ci`, затем при необходимости `npx playwright install chromium`. Версия Playwright зафиксирована в `package-lock.json`. Эти зависимости не требуются пользователю готовой страницы. Ранние проверки выполнялись в установленном Edge, итоговый прогон — в установленном Chrome 155.0.8059.85; браузеры для проверки не скачивались.

## Данные и ограничения

- IndexedDB: база `construction-planner`, версия 1, хранилище `state`, запись `main`. Хранит проекты, историю, настройки, поколение базы и служебную отметку учебного примера. Обновление записи выполняется одной транзакцией с проверкой поколения.
- План сохраняется на том же адресе и в том же профиле браузера. Очистка данных сайта может удалить его. Внешней отправки планов нет.
- Аварийная копия при ошибке записи включает согласованный сохранённый план и отдельно несохранённые поля формы. Это диагностическая копия, не обычный файл обмена. Храните её как финансовые данные.
- Финансовая сводка готова: раздел «Финансы» → выбор периода, объектов и категорий → нажатие суммы для её детализации. Из детализации можно открыть ресурс и изменить платежи; таблица и детализация пересчитываются после сохранения. Общая стоимость всегда показана за весь план, сумма к оплате — за выбранный период.
- Работают обмен JSON, полное восстановление, окончательное удаление, Гант, печать и подготовка офлайн. Установка предлагается при поддержке браузером; доступность системной команды зависит от устройства.
- `file-format.schema.json` описывает формат 1. Генератор — `tools/schema.js`. Прикладные проверки дополняют структурную схему: даты, уникальность ID, связи и пределы агрегатов.
- Реальные Android/iPhone и их системные календари не считаются проверенными настольной эмуляцией.

## Как обмениваться планами

1. Договоритесь, кто сейчас редактирует объект. На его странице нажмите «Скачать объект» либо используйте «Скачать план» → «Скачать выбранный объект». Передайте сохранённый JSON привычным способом вне приложения.
2. Получатель нажимает «Загрузить план», выбирает файл и изучает отличия. По умолчанию новый объект добавляется, продолжающая редакция заменяет локальную, устаревшая или конфликтующая — пропускается. До записи можно поменять выбор.
3. При конфликте скачайте обе версии. Автоматического слияния нет: пользователь выбирает целую копию и при необходимости повторяет отдельные правки вручную. Дата файла не доказывает его актуальность.
4. После подтверждения изменяются только выбранные объекты. Остальные планы и настройки устройства сохраняются. Повторный импорт той же редакции не создаёт дубликаты. В настройках доступен результат последней загрузки.

Полный файл по умолчанию тоже добавляет/обновляет выбранные объекты. Режим «Восстановить полную копию» заменяет весь набор, включая удаление отсутствующих в файле. Он требует фразу «ЗАМЕНИТЬ ВСЕ ДАННЫЕ» и предлагает резервную выгрузку. Перед применением весь файл и итоговый набор проверяются; при ошибке запись откатывается целиком.

## Резервное копирование и удаление

«Скачать все объекты» включает активные планы, архив, историю и отметки удаления. Проверяйте, что файл действительно сохранён; сайт не может подтвердить физическую запись на диск. Отдельный объект не заменяет полную копию. При расхождениях стоимости и платежей можно проверить список и затем явно выбрать «Выгрузить как есть».

Напоминание появляется через 24 часа после предыдущей полной выгрузки при новых пользовательских изменениях; до первой полной копии отсчёт ведётся от первой пользовательской правки. «Позже» скрывает напоминание на 24 часа. Учебный пример сам по себе не запускает отсчёт. Проверка выполняется при запуске и сохранении, без фоновых уведомлений.

Опциональный запрос устойчивого хранения находится в настройках; отказ не блокирует работу. Даже разрешённое устойчивое хранение не защищает от явной очистки данных сайта и не заменяет внешний файл.

Окончательное удаление предлагает резервную копию. Для объекта и этапа введите точное название; при оплаченных платежах требуется отдельное подтверждение. Дочерние записи удаляются вместе. Общие расходы не относятся к этапам. После удаления объекта остаётся только служебная метка ID/названия/даты; его финансовые подробности исключаются также из результата последнего импорта. Корзины нет.

## Локальные метаданные файлов

В той же транзакционной записи `state/main` добавлено необязательное поле `fileMeta`: редакции выгруженных объектов, сведения о полной копии, начало отсчёта пользовательских правок, отсрочка напоминания и результат последнего импорта. Эти сведения не входят в JSON формата 1. Для ранее созданной базы они выводятся из имеющихся данных без очистки и без изменения объектов; версия IndexedDB остаётся 1.

Предельный размер входящего файла — 20 МиБ. Кодировка UTF-8, расширение `.json`. Запрещены неизвестные поля и коды, опасные ключи, повторные ID, чрезмерная вложенность (более 64 уровней), недопустимые даты и суммы. Файл не исправляется молча. Ошибки содержат путь к записи. JSON сохраняется без шифрования и доступен его получателю.

## Офлайн и обновление

Откройте HTTPS-страницу либо localhost и дождитесь внизу сообщения «Готово к работе без интернета». После этого тот же адрес доступен без сети; локально работают редактирование, расчёты, Гант, выгрузка и загрузка JSON. Если подготовка не удалась, подключите сеть и нажмите «Повторить подготовку». Успешное открытие страницы само по себе ещё не означает готовность офлайн.

Service worker хранит только 22 файла интерфейса и локальных иконок. Планы остаются в IndexedDB, выгрузки не кешируются. Удаление кеша интерфейса не удаляет планы; очистка всех данных сайта удалит и базу. Резервная копия JSON по-прежнему необходима.

«Есть обновление приложения» означает, что новая версия полностью скачана и проверена. Кнопка «Применить обновление» доступна после сохранения/закрытия форм и предпросмотра. Если обновление применили в другой вкладке, вкладка с открытым вводом сохраняет его до завершения работы и явного применения. Обновление файлов приложения не создаёт новую пустую базу. Неполная поставка или несовпадение SHA-256 не заменяет работающую офлайн-версию.

Кнопка «Установить» появляется, когда браузер предоставляет предложение установки; она вызывает системный диалог только по нажатию. На устройствах с собственной командой добавления на главный экран используйте её при наличии. Реальная установка и сохранность данных между браузером и установленной копией зависят от устройства: автоматический перенос не обещается. Перед сменой адреса, профиля или режима запуска скачайте JSON.

## Статическое размещение

Публикация не выполнялась. Комплект для размещения: `output/release/stroiplan/`, готовый архив — `output/release/stroiplan-static.zip`. Это только интерфейс, без тестовых и пользовательских планов. Исходники, схема, тесты, документация и отчёты находятся в папке проекта.

После получения исходников из Git, перед первым размещением и после изменения любых файлов интерфейса или `sw.js` выполните:

```sh
npm run release
```

Команда обновляет `app-assets.js` с версией и SHA-256, затем копирует 24 файла поставки. Проверка комплекта:

```sh
npm run test:release
```

Для неё должен работать локальный сервер на 4173. `app-assets.js` не редактируют вручную. ZIP — снимок поставки: после новых правок его также пересоздают из свежей папки. В PowerShell:

```powershell
Compress-Archive -Path output/release/stroiplan/* -DestinationPath output/release/stroiplan-static.zip -Force
```

Разместите содержимое папки на статическом HTTPS-хостинге с сохранением структуры; поддерживается корень и подпапка вида `/planner/`. Сборка, сервер приложения, API и базы на хостинге не нужны. Не загружайте туда всю папку проекта, JSON-планы, Git, тесты и отчёты. Для JS нужен MIME `text/javascript`, для manifest — `application/manifest+json`; `sw.js` и `app-assets.js` должны получать актуальную версию без длительного HTTP-кеша. Не подменяйте запросы JS/CSS HTML-страницей. Комплект новой версии заменяйте целиком, предпочтительно одной атомарной публикацией; смешанные версии не проходят проверку целостности.

После размещения откройте адрес, дождитесь готовности офлайн, отключите сеть и повторно откройте его. Перед следующим обновлением исходников заново выполните подготовку комплекта. Адрес и профиль браузера определяют локальную базу: перенос на другой домен/порт не переносит данные. Самостоятельная резервная выгрузка и загрузка на новом адресе сохраняют планы.

## Полный набор проверок

При работающем локальном сервере:

```sh
npm test
npm run test:release
npm run test:browser
```

`test` проверяет логику и пределы, `test:release` — комплект/хеши/схему/MIME/закрытые пути, `test:browser` последовательно запускает десять изолированных браузерных наборов. Нужен установленный Playwright; можно задать `PLAYWRIGHT_MODULE` и `BROWSER_PATH`, как описано выше. Наборы не используют ваш браузерный профиль. `tests/offline-browser.cjs` поднимает отдельный временный сервер в подпапке; `tests/acceptance-browser.cjs` измеряет инженерный объём ТЗ на фактическом компьютере; `tests/journey-browser.cjs` проходит весь процесс в двух независимых профилях.

Для повторного получения 14 контрольных PDF текущей печати задайте `GENERATE_PDFS=1` перед `npm run test:browser`. Старый набор Ганта в общем прогоне проверяет поведение без перезаписи исторических PDF. Затем выполните `tools/check-gantt-pdf.py --compact` с Python/pdfplumber/Pillow и переменной `PDFTOPPM` до Poppler. После отдельных успешных прогонов `node tools/report-checks.js` собирает сводку из всех десяти отчётов с проверкой количества сценариев и отсутствия ошибок. Итоговая матрица требований и ограничения устройств — `output/step5-checks.md`, машинные результаты — `output/step5-*-results.json`, замеры — `output/step5-performance.json`.

Входящий файл и каждый итог записи проверяются до фиксации; данные не обрезаются. При отказе формы сохраняют ввод. Для старого превышения после миграции разрешено действие, действительно уменьшающее его, без роста остальных превышенных показателей или появления нового превышения. Проверка выполняется по свежему состоянию внутри транзакции. История и архив автоматически не сокращаются.

Ресурсы/платежи выводятся по времени создания, затем ID; работы/этапы — по сохранённому порядку. Изменение комментария работы не перемещает её. Порции также добавлены внутри крупного события истории и в архиве.

Новый набор: `node tests/audit-block1-browser.cjs` (входит в `npm run test:browser`). Отчёт — `output/audit-block1-checks.md`. D05–D09, реальные устройства и размещение остаются отдельными открытыми пунктами.
