# Стройплан — шаги 1–2

Локальный план строительных объектов. Реализуемый объём и история — в `plan.md`, требования — в `tz.md`.

## Запуск для разработки и просмотра

При установленном Node.js выполните в папке проекта:

```sh
node tools/serve.js
```

Откройте http://127.0.0.1:4173. Для постоянного использования нужен статический HTTPS-сайт; публикация пока не выполнялась. Двойной щелчок по `index.html` не является поддерживаемым запуском. Сборка и установка библиотек для интерфейса не нужны.

## Проверки

```sh
node --test tests/domain.test.js
node tools/schema.js
```

Браузерные проверки: `node tests/browser.cjs`, `node tests/browser-deep.cjs` и `node tests/finance-browser.cjs` при доступном пакете `playwright` и браузере Chromium. Если пакет находится вне проекта, задайте `PLAYWRIGHT_MODULE` абсолютным путём к нему; для установленного Chrome/Edge задайте `BROWSER_PATH` абсолютным путём к исполняемому файлу браузера. Сервер должен работать на порту 4173. Проверки используют отдельные временные браузерные контексты, а не пользовательские данные. Проверка полного перезапуска создаёт отдельный временный профиль в системной папке временных файлов. `npm test` запускает тесты как основной логики, так и финансового расчёта.

Для установки только инструментов разработки: `npm ci`, затем при необходимости `npx playwright install chromium`. Версия Playwright зафиксирована в `package-lock.json`. Эти зависимости не требуются пользователю готовой страницы. В текущей среде проверки выполнены с уже установленными Playwright и Edge, без скачивания браузера.

## Данные и ограничения текущего шага

- IndexedDB: база `construction-planner`, версия 1, хранилище `state`, запись `main`. Хранит проекты, историю, настройки, поколение базы и служебную отметку учебного примера. Обновление записи выполняется одной транзакцией с проверкой поколения.
- План сохраняется на том же адресе и в том же профиле браузера. Очистка данных сайта может удалить его. Внешней отправки планов нет.
- Аварийная копия при ошибке записи включает согласованный сохранённый план и отдельно несохранённые поля формы. Это диагностическая копия, не обычный файл обмена. Храните её как финансовые данные.
- Финансовая сводка готова: раздел «Финансы» → выбор периода, объектов и категорий → нажатие суммы для её детализации. Из детализации можно открыть ресурс и изменить платежи; таблица и детализация пересчитываются после сохранения. Общая стоимость всегда показана за весь план, сумма к оплате — за выбранный период.
- Обмен JSON, обычное окончательное удаление, Гант, печать, офлайн и установка относятся к следующим шагам. Нет неработающих кнопок этих функций.
- `file-format.schema.json` описывает формат 1. Генератор — `tools/schema.js`. Прикладные проверки дополняют структурную схему: даты, уникальность ID, связи и пределы агрегатов.
- Реальные Android/iPhone и их системные календари не считаются проверенными настольной эмуляцией.
